Privacy and security

Privacy rules that live in the data layer

Members decide who sees their build, photos are cleaned before anyone sees them, and deleting an account deletes its data.

The model

A build is public unless its owner makes it private. Public by default helps people find builds like theirs, so the protections behind it have to be built into the system.

They live on the server and in the database. A member can't turn them off, and a new feature can't forget them.

The systems behind it

A photo privacy pipeline

Every uploaded photo goes through a pipeline before anyone else can see it. It finds license plates, faces, VINs and addresses and blurs them, strips location and camera data, and stores the result privately behind links that expire within the hour. The original is never handed back, and if any step fails, the photo isn't published.

Data walled off in the database

Row-level security keeps a member's private data to that member in the database itself as well as in the app. About 85 tables are tied to each account, so deleting an account removes every row and every stored file it ever created.

Moderation the database enforces

The content filter blocks slurs and self-harm taunts, even with disguised spellings, while swearing and car slang stay allowed. On messages, clubs and profiles it runs as a database trigger, so no screen, old or new, can skip it. Anything can be reported, and every report gets a review.

Security tested against the live app

A suite of 89 security checks runs against the running app as well as the code. Every route is rate limited per member, and if the limit can't be checked, the request is refused.
